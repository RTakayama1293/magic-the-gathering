# 判断基準

最終更新: 2026-10-31（たたき台。ユーザーと相談して直していく）

勝率を上げる判断は、メタの読み、デッキ選択、構築、SB、プレイ、振り返りの層に分かれる。層ごとに何を根拠にどう判断するかをこのファイルに書き、Claudeとユーザーの判断をこの基準に照らして行う。

この基準を作る理由は、2026-10-31にユーザーとClaudeが次の点を確認したため。Claudeの戦略の価値判断は不正確なことが多い。ユーザー自身も戦略の判断に自信がない。汎用AIが将棋で強くないのと同じで、Claudeが一般的な知識から出す戦略の評価はそのまま信用できない。このため、判断の手順と根拠の基準を先に決め、個々の判断をその基準で検証できるようにする。

## 1. 根拠の種類と重み

判断を書くときは、根拠の種類を必ず一緒に書く。

| 種類 | 例 | 扱い |
|---|---|---|
| ルールとカードテキスト | `oracle/cards.csv`、Scryfallの裁定 | 事実として扱う。記憶で書かない |
| 自分の戦績 | Notion戦績DBのMatch # | 試合数に応じて扱う（2章） |
| 外部の大会結果・使用率 | URLと集計期間が付いたもの | 事実として扱う。ただし自分の環境（Arenaのランク帯、紙の大会）と母集団が違う |
| ユーザーの判断 | 対戦中の感覚、構築の方針 | 方針（4章）として記録したものは前提として使う |
| Claudeの推論 | 他フォーマットからの類推、理論上の計算、一般論 | 仮説として扱う。上の3つと食い違ったら取り下げる |

## 2. 試合数と結論の強さ

勝率の推定には幅がある。下の表は、勝率の95%信頼区間（Wilsonの方法）を計算したもの。

| 戦績 | 勝率 | 本当の勝率の範囲（95%） |
|---|---|---|
| 1勝1敗 | 50% | 9%〜91% |
| 3勝2敗 | 60% | 23%〜88% |
| 5勝5敗 | 50% | 24%〜76% |
| 10勝10敗 | 50% | 30%〜70% |
| 25勝25敗 | 50% | 37%〜63% |
| 50勝50敗 | 50% | 40%〜60% |

このため、記録の書き方を次のように決める。

- 対面の有利不利: 5試合未満では「有利」「不利」と書かない。「n試合でx勝y敗」と事実だけを書く
- 1試合で起きたこと: 「この試合ではこうなった」と書き、原則にはしない。同じことが2試合以上で起きたら原則の候補にする
- デッキ全体の勝率: 20試合未満では、デッキ間の勝率の比較に使わない
- 勝敗の数字より、試合の中で何が起きたか（どのカードで負けたか、どのターンに何が足りなかったか）の記録を優先する。勝敗は試合数が少ないうちは偶然の影響が大きい

参考: 2026-10-31時点の戦績DBでは、Soulflayerが102試合で37勝65敗（範囲28%〜46%）、Archfiend Alterationが18試合で9勝9敗（範囲29%〜71%）。

## 3. 層ごとの判断基準

### 3-1. メタの読み

- 根拠: 出典URLと集計期間のある使用率・大会結果だけを使う。手順は `.claude/skills/meta-update/SKILL.md`
- Arenaのラダーと紙の大会では、出てくるデッキが違うことがある。自分の戦績DBの対戦相手の分布も、メタの資料と並べて見る
- 未決: Arenaのラダーで当たる相手の分布を、戦績DBから定期的に集計するか

### 3-2. デッキ選択

- 判断の材料: 上位デッキへの戦績（自分のDB）、外部の大会結果、ユーザーがそのデッキを使いこなせるか
- 未決: 上の3つの材料が食い違ったとき、どれを優先するか

### 3-3. 構築

ユーザーの方針（4章）を前提にする。カードの採否は、次のどれかを根拠に書く。

- カードテキストから確実に言えること（マナ総量、対象にできるもの、誘発条件）
- 戦績DBで、そのカードが勝敗に関わった試合
- 外部の上位リストでの採用枚数

「強い」「弱い」だけの評価は書かない。何に対して、どの場面で、何をするから採るのかを書く。

### 3-4. サイドボード

- SBプランは対面ごとに、IN・OUT・ねらい（G2以降に何をして勝つか）を書く
- プランを実際に使った試合のMatch #を一緒に書く。使っていないプランは「未検証」と書く
- 未決: SB後のゲーム（G2・G3）だけの勝敗を別に集計するか

### 3-5. プレイ

- その時点で見えていた情報での期待値で判断を評価する。結果で評価しない
- プレイの原則は `notes/play_learnings.md` に書く。根拠のMatch #と試合数を書く

### 3-6. 振り返り

- 負けを「構造的な負け」「プレイミス」「上振れ・下振れ（分散）」に分ける
- 「構造的な負け」と書けるのは、同じ対面で同じ形の負けが2試合以上あるときだけにする。1試合なら「構造的な負けの可能性」と書く

## 4. ユーザーの構築方針

ユーザーが決めた方針で、構築の前提として使う。Claudeの推論でこれを覆さない。

- メインのカード種類を少なくし、1種類の枚数を厚くする。汎用カードで固める
- サイドボード後にデッキの戦い方を変えて、相手の読みを外す
- 同じ資源を使って勝つ手段が複数あるのは強みとして扱う。例: the spyは欄干のスパイ（Balustrade Spy）と地底街の密告人（Undercity Informer）を4枚ずつ入れる。1ゲームの中でどの手段を使うかは、その場の状況で選ぶ

## 5. 未決の論点

ユーザーと決める。

1. デッキ選択で、自分の戦績・外部の大会結果・使いこなせるかが食い違ったときの優先順位
2. 対面の有利不利を書いてよい試合数の下限（たたき台では5試合）
3. SB後のゲームの勝敗を別に集計するか
4. Arenaのラダーと紙の大会で、判断基準を分けるか
